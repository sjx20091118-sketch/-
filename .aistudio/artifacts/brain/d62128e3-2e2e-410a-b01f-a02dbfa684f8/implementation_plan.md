# 《拾年》QQ 邮箱与通用 SMTP 邮件网关底层响应透传、双端口独立测速与专属 3 步排查向导实施方案

经过对云端与真实发信链路的底层探测验证：服务端到 `smtp.qq.com:465` (SSL) 与 `smtp.qq.com:587` (STARTTLS) 的 TCP/TLS 网络连接完全畅通（IPv4 DNS 解析正常）。此前诊断提示“网络握手或授权异常”的根因在于前端将所有非 200 响应统一归为该标题，未能将 QQ 邮箱服务器返回的底层响应码（如 535 Login fail、553 等）与具体排查步骤清晰分层呈现。

本方案提供全方位的底层响应透传、双端口独立测速与 QQ 邮箱专属 3 步排查向导。

---

## 一、 核心功能与实施计划

### 1. 协议底层真实响应透传与智能分类诊断
- 在服务端 `/api/admin/test-smtp` 中：
  - 完整透传邮件服务器返回的 `code`、`responseCode`（如 535、553、501、ETIMEDOUT 等）及原始英文响应信息（`rawResponse`）；
  - 针对 QQ 邮箱专属错误定制结构化指引：
    - **535 认证失败**：明确告知“QQ 邮箱专属 16 位授权码错误或 POP3/SMTP 服务未开启”，并提供 3 步快速排查向导；
    - **553/501 发件人地址不一致**：提示 User 必须与授权码所属账号完全一致；
    - **连接或超时异常**：展示具体握手耗时与建议切换端口。

### 2. 双端口（465 SSL 与 587 STARTTLS）独立测速与指示灯
- 在管理后台灵台（`AdminPortal.tsx`）的 SMTP 配置面板中：
  - 增加 **465 SSL** 与 **587 STARTTLS** 独立端口切换测试按钮；
  - 增加发信握手状态指示灯（🟢 绿灯通过 / 🟠 橙灯警告 / 🔴 红灯异常）与真实网络耗时显示（如 `耗时: 342ms`）；
  - 详细展示测试发信的 `Message-ID` 与测试验证码。

### 3. QQ 邮箱专属 3 步排查向导直接嵌入 UI
在诊断结果区域直观呈现：
1. **第一步**：严禁使用 QQ 登录密码，必须使用 QQ 邮箱网页端生成的「16 位专属授权码」；
2. **第二步**：登录 QQ 邮箱网页端（mail.qq.com）➔【设置】➔【账户】➔ 确认【POP3/IMAP/SMTP 服务】处于开启状态；
3. **第三步**：若授权码曾在其他设备重新生成过，旧授权码会自动失效，请点击【生成新授权码】并填入后台。

### 4. 授权码与账号不可见字符自动清洗
- 前端输入与后端处理均自动剥离零宽空格（`\u200B`、`\u200C`、`\u200D`、`\uFEFF`）、不换行空格（`\u00A0`）及普通空格换行，防止复制授权码时被污染。
